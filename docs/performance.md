## 2. 测量方法

- 每轮为两端分别创建空下载缓存；冷安装前安装集合为空。
- 热安装重新清空安装状态和本轮产生的可变配置，保留各自下载或准备缓存，然后再次执行完整安装。它验证的是“热缓存重新安装”，不是保留所有已有配置的 `reinstall` 命令语义。
- 每次冷、热安装都运行证书初始化，并在计时外执行 hello、jq 和证书结果检查。包集合与 package version 必须完全匹配。
- 比较值为完整命令进程的单调时钟耗时。阶段计时用于诊断，磁盘遍历和结果验证均在计时外。
- gobrew 的 `update` 与 Homebrew 的 `info --json=v2` 在安装计时前执行，并单独记录；两者并非相同的目录刷新操作，未将该列用于安装门禁。各自该列中位数为 1.721 秒、0.330 秒。
- 使用独立非默认 prefix，两条具体路径写入原始报告。Homebrew 通过其正式 `--force-bottle` 选项安装；未修改 Homebrew 代码，未跳过依赖、链接、校验或初始化。路径长度会影响重定位工作，不能把此环境等同于默认 `/opt/homebrew`。
- Homebrew 的缓存、日志、配置目录和临时目录均隔离。日常 Homebrew 安装未被修改。最初一次尝试在 Homebrew 的临时目录检查处停止，没有形成有效对照，未计入这五轮。
- 没有声称清空操作系统页缓存；网络、系统信任检查与系统缓存仍可能波动。五轮始终先测 gobrew 再测 Homebrew，没有据此推导统计置信区间。

复现命令中的 Homebrew 必须是初始无 Formula 的独立安装：

```sh
scripts/benchmark.sh \
  --gobrew "$PWD/bin/gobrew" \
  --brew /path/to/disposable/Homebrew/bin/brew \
  --rounds 5 --require-faster > benchmark.json
```

脚本拒绝默认 Homebrew prefix、已有 Formula 和会覆盖隔离配置的 `brew.env`。失败也输出部分证据；发布工作流只在完整门禁通过后发布同一被测二进制。

## 3. 阶段与瓶颈

以下分别取各阶段五次样本的中位数，因此不能将各列简单相加当作端到端中位数。

| 场景 | Plan | Prepare | Apply |
| --- | ---: | ---: | ---: |
| 冷安装 | 0.479 毫秒 | 2841.178 毫秒 | 7323.219 毫秒 |
| 热安装 | 0.878 毫秒 | 0.932 毫秒 | 7206.593 毫秒 |
| no-op | 0.922 毫秒 | 0 | 0 |

独立临时实验把证书包初始化脚本测为 6.593 秒，后置树同步约 6.49 毫秒，24 次 bbolt 更新约 148 毫秒。该脚本对每份证书串行启动多次 `security`、`openssl` 等进程，是此集合热安装的主要开销。保留完整上游初始化行为比报告一个跳过该阶段的数字更重要。

已根据测量完成两项内部优化：

1. 对同一持久化日志内的链接变化批量刷新目录，刷新成功后才提交；失败和中断恢复测试保持通过。
2. 计划通过 bbolt key 读取请求根、已安装包及当前依赖闭包，避免每次解码全部 8,679 条记录。别名或缺失 key 在同一事务安全回退全量读取。

第二项的 5 次本地微基准：全量读取 54.83 毫秒、28.22 MB 分配；4 包闭包读取 0.133 毫秒、15.85 KB 分配；Node 的 25 包闭包读取 0.281 毫秒、79.62 KB 分配。这些仅为目录读取数据，不能当作整次安装的提速倍数。
