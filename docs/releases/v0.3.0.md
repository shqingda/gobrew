# gobrew v0.3.0

本版让 gobrew 开箱即用：不再需要手动初始化和配置 PATH，安装过程与命令语义对齐 Homebrew。Formula 安装位置和已有软件数据不变。

## 安装

支持 Apple Silicon、macOS 15 或更新版本；运行发布程序不需要安装 Go。

```sh
curl -fsSL https://github.com/shqingda/gobrew/releases/latest/download/install.sh | sh
```

安装器会安装 `gobrew` 和 `gob` 命令、准备 Formula 目录，并把 gobrew 加入新终端的 `PATH`。装完后新开一个终端（或执行 `exec zsh`），即可运行 `gob install uv`。

## 从 v0.2.0 升级

v0.2.0 的 `update` 只刷新 Formula 目录，因此这一次请用自身更新命令：

```sh
gob self update
```

之后执行任意 `gob install`，gobrew 会补齐 Formula 目录和 PATH 配置。从本版起，`gob update` 已包含自身更新。

## 不再需要手动 init

- curl 安装器在安装命令后直接初始化 Formula 目录；未完成时，第一次 `gob install` 或 `migrate` 自动补齐。
- 默认目录 `/opt/gobrew` 首次创建需要管理员权限时，程序说明原因并通过 `sudo` 在终端中请求一次密码。提权进程只创建 `/opt`（若不存在）和该新目录并交给当前用户，不联网、不运行软件包代码、不修改已有目录所有权，也不触碰 `/opt/homebrew`。之后的安装、升级和卸载都不需要 `sudo`。
- 没有可交互终端或使用 `--json` 时不请求密码，而是返回 `privilege_required` 错误和一条带绝对路径的命令。`--dry-run` 与只读命令不创建目录。
- `gobrew init` 保留为幂等的预初始化和修复入口，可补全中断留下的空目录结构，拒绝接管其他内容。

## PATH 自动配置

- 在 shell 启动文件末尾写入一段 `# >>> gobrew >>>` 到 `# <<< gobrew <<<` 的配置（zsh 为 `.zshrc`，bash 为已有的登录配置文件，fish 为 `conf.d/gobrew.fish`），把命令目录和 `/opt/gobrew/bin`、`/opt/gobrew/sbin` 放在 `PATH` 最前面。
- 只修改标记之间的内容，重复执行不重复添加，`self uninstall` 时移除；标记损坏、不属于当前用户或有多个硬链接的文件不会被改动。
- 当前终端已包含这些目录时不读写配置文件；自定义 `--prefix` 不写入；`GOBREW_NO_MODIFY_PATH=1` 可关闭。
- `GOBREW_PREFIX`（由 `shellenv` 导出）现在也作为 `--prefix` 的默认值。

## 与 Homebrew 共存

gobrew 与 Homebrew 各自管理自己的目录，互不覆盖。同名命令在新终端中默认运行 gobrew 的版本。`gob install` 发现 Homebrew 也提供同名命令时会提示，并给出可选的 `brew uninstall` 命令；`gob doctor` 以警告形式报告同名命令和 `PATH` 顺序，不影响退出码。gobrew 只读取 Homebrew 的文件。

## 输出与命令

- 安装过程采用 Homebrew 风格的 `==>` 步骤标题，终端中显示合并的下载进度条，结束时每个包显示 `<keg>: N files, SIZE`，并显示注意事项和“已是最新”提示。非终端与 `--json` 输出不含进度条和颜色。
- `gob update` 与 `brew update` 一致：先更新 gobrew 自身，再刷新并校验 Formula 目录，最后列出可升级的软件。`gob upgrade` 不带名称时升级全部未 pin 的软件。
- `doctor --json` 的结果项新增可选的 `severity` 字段；`update --json` 的结果新增 `cli` 和 `outdated` 字段，原有字段不变。

## 发布资源与检查

发布资源包含 ARM64 压缩包、安装脚本、`checksums.txt` 和本次二进制的 `benchmark.json`。将四个文件下载到同一目录后，可运行 `shasum -a 256 -c checksums.txt` 验证。校验文件与压缩包来自同一 GitHub 信任域，不构成独立签名。

发布流程要求通过代码检查、CLI 引导安装与自身生命周期测试、macOS 实机 Formula 烟测及五轮性能门槛。具体运行结果以对应 GitHub Actions 和随附基准数据为准。
