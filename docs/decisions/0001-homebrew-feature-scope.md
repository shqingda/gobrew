# 001：Homebrew 功能取舍

## 状态与日期

已接受，2026-10-28（Asia/Taipei）。用户要求将本次讨论的功能取舍记录到项目文档。

这是后续开发范围的决定，不代表功能已经实现，也不要求删除现有功能。此前交接或计划中的全量 Homebrew 对齐目标与本记录冲突时，以本记录为准。

## 背景

gobrew 面向官方 Homebrew core 预编译软件的快速安装和可靠管理。常用命令应符合用户习惯，但不以复制 Homebrew 全部功能、参数及内部机制为目标。功能价值按实际使用场景和长期维护成本判断，不将缺少某个 Homebrew 入口自动视为待修复问题。

## 不纳入开发范围

| 功能 | 取舍依据 |
| --- | --- |
| Formula 开发工具，如 `create`、`edit`、`audit`、`bottle`、`test` | 主要服务包维护者，不属于普通安装用户的核心流程。 |
| 源码构建、编译选项、`--HEAD` | 编译环境、补丁与构建差异的维护成本高，偏离预编译安装定位；维持不执行 Ruby、不回退 Homebrew 的约束。 |
| Homebrew 自身 Git 仓库管理，如 `update-reset`、`--repository` | gobrew 使用自己的目录与程序更新机制，无须复制 Homebrew 的内部结构。 |
| `--ignore-dependencies` | 会允许缺依赖的安装，增加运行故障和排查负担。 |
| 全套环境变量、所有参数及提示语逐字兼容 | 保持日常操作习惯，按实际需求增加兼容项，不承担完整复刻的持续维护成本。 |

## 低优先级或按需实现

| 功能 | 决定 |
| --- | --- |
| `home`、独立 `desc`、`log` 等辅助入口 | 低优先级；官网、描述和历史链接优先集中到 `info`。 |
| 完整 `bundle` 生态 | 暂不做。导出和恢复软件清单有价值，可单独评估；不因此扩展到编辑器扩展或其他包管理器的管理。 |
| Homebrew JSON 格式完全兼容 | 仅在存在具体的 brew 脚本兼容需求时评估；保留 gobrew 自己稳定的 JSON 接口。 |
| 第三方 tap、`services`、Cask、漏洞查询 | 有明确使用价值，但延后，待具体需求再排期。tap 仍受不执行 Ruby 和元数据信任约束限制；本记录不放宽这些约束。 |

## 依赖方升级的边界

因库变化导致依赖方无法正常运行时，必要的重装、升级或明确拒绝操作属于正确性要求，不能省略。现有依赖与 ABI 检查继续保留。

仍能正常运行、仅版本过时的依赖方，其自动升级不再作为当前 P0 必做项；先延后评估，避免安装一个软件时扩大变更范围和耗时。对应 `GOBREW_NO_INSTALLED_DEPENDENTS_CHECK` 开关不单独列为必做项。此次只调整范围，不宣称已实现完整的损坏链接检测或修复。

## 必须保留的能力与验证

- 依赖正确性、升级后的可运行性、签名与摘要校验、失败恢复。
- 卸载、清理和 PATH 诊断。
- 真实安装链路验证、当前版本性能重测及既定的 nanobrew 同机对比任务；不能用缩减功能范围代替这些验证。

## 后果与参考

后续任务清单应区分正确性缺口、按需功能与明确不做的功能。已有实现无需为本次范围调整而删除；不支持的能力应如实说明，不能声称与 Homebrew 完全兼容。

功能语义参考 [Homebrew 官方手册](https://docs.brew.sh/Manpage)；上述优先级是 gobrew 的产品取舍，不是对 Homebrew 用户使用频率的统计结论。
